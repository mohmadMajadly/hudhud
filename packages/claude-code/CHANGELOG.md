# @hudhudjs/claude-code

## 0.1.0

### Minor Changes

- c42acf0: The stability promise is now exact (pre-release review R5-1, ADR-0004 amendment). Stable, under semver: the root entries of `hudhudjs`, `@hudhudjs/core` and `@hudhudjs/claude-code` (except the adapter-author items `defineAdapter`, `AdapterDefinition`, `buildPosture` and `PostureEntryInput`), the schemas, and from `@hudhudjs/core/protocol` the application helpers `sanitizeForDisplay`, `SanitizeForDisplayOptions`, `parseErrorData`, `ErrorDataFailure` and `isRetryable`. Beta, for adapter authors, and free to change in a minor version: `@hudhudjs/core/process` (which was documented as stable), the rest of `@hudhudjs/core/protocol` (the machine contract, the JSON line helpers, exit classification, `ERROR_RETRYABLE`, `makeErrorData`, `isHudhudErrorCode`), `@hudhudjs/core/binding`, and the raw tier `@hudhudjs/claude-code/raw`, which also stays exempt from compatibility promises. Nothing was renamed or removed; only the release tags (`@public` to `@beta`) and the documentation changed.
- a99a908: The tested window of the Claude Code adapter spans several releases: `CLAUDE_CODE_COMPAT` is `minTested: '2.1.296'`, `maxTested: '2.1.302'`, and every release in between (2.1.299, 2.1.300, 2.1.301) was tested too. Users on any of them get `compat.status: 'tested'` instead of `'untested'`. The committed digest table holds the official binaries of all five releases on linux-x64, win32-x64, darwin-arm64 and darwin-x64, each checked against the npm integrity and the Agent SDK `manifest.json` of the same CLI release, so `binary.verification` is `'verified'` for them without `claudeCode.binaryDigests`. From 2.1.299 on, Claude Code no longer sends the `anthropic-beta` value `mid-conversation-system-2026-04-07`; nothing in hudhud depends on it.
- e4f9fe6: A session started on a Claude Code version outside the tested window publishes the diagnostic `compat.untested` among its start diagnostics (`data` is the `compat` object: `version`, `minTested`, `maxTested`, `knownBroken`, `status`). It is a warning only: the session runs, as before. `DiagnosticCode` and the events schema list the new code (additive). Before, an untested version showed only in `harness.compat` and the `compat` event.
- 19ef5d6: The committed digest table holds the darwin-arm64 and darwin-x64 binaries of CLI 2.1.296 (sha256 and size recorded by the macOS gate, cross-checked against the npm integrity and the Agent SDK `manifest.json`; research 10 §5, research 11). A pinned darwin binary is now `verified` in advisory and strict mode without `claudeCode.binaryDigests`.
- 6c52857: Strict binary verification on macOS requires the pinned publisher (macOS gate, research 11).
  
  - `@hudhudjs/core/process`: `PublisherPin.darwinTeamId` (new). The macOS signature check runs `/usr/bin/codesign --verify --strict -R <requirement>`, where the requirement is a Developer ID designated requirement whose leaf organizational unit is the pinned Team ID (`anchor apple generic`, a Developer ID intermediate, a Developer ID Application leaf). A valid signature by another team fails (`codesign failed: exit 3`). Without a Team ID, or with one that is not 10 upper-case letters or digits, the check fails without running codesign, as the Windows check fails without a pinned subject. The verification cache is keyed by the Team ID.
  - `@hudhudjs/claude-code`: `CLAUDE_CODE_PUBLISHER.darwinTeamId` is `Q6L2SF6YDW` (Anthropic PBC, recorded from the signed darwin-arm64 and darwin-x64 binaries of CLI 2.1.296).
- c965807: The project credential guard (`projectCredentialEnv: 'refuse'`, the default whenever project or local settings load) now refuses the third-party provider routing and credential variables too, by family rather than by an exact list: every `ANTHROPIC_*`, `AWS_*`, `GOOGLE_*`, `GCLOUD_*`, `CLOUDSDK_*`, `CLOUD_ML_*`, `VERTEX_*`, `AZURE_*`, `CCR_*` and `CLAUDE_CODE_USE_*` variable except model selection (`ANTHROPIC_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL`, `ANTHROPIC_DEFAULT_*_MODEL` and their display companions); `CLAUDE_*` variables with a credential, routing or configuration segment (`CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CODE_API_BASE_URL`, `CLAUDE_CONFIG_DIR`, ...); every proxy variable except the `NO_PROXY` forms; and every TLS-trust variable. Before, a repository could set `CLOUD_ML_REGION`, `AWS_REGION` or `ANTHROPIC_FOUNDRY_RESOURCE`, from which Claude Code builds the provider host, and receive the provider credential. A repository that sets such a variable is now refused with `PROJECT_CREDENTIAL_ENV`; set the variable from the application with `env.add`, or opt in with `projectCredentialEnv: 'allow'`. The names are also listed in `securityPosture` (`env.credentialAndRoutingVariables`) when the application sets them.
- 3b3194f: K10: auth fail-fast covers `ANTHROPIC_AUTH_TOKEN` as well as `ANTHROPIC_API_KEY` (lead decision after the recorded `auth-token-source` fixture: a static env credential that got a 401 does not succeed on retry). The CLI reports the token as `account.tokenSource: "ANTHROPIC_AUTH_TOKEN"` with `apiKeySource: "none"`, so `SessionInfoData` and the `session.started` event gain the optional `tokenSource`; fail-fast matches `apiKeySource` or `tokenSource` against `authFailFastSources` (default both env credentials), and the `AUTHENTICATION_FAILED` details name the triggering credential (`credentialSource`). OAuth and `apiKeyHelper` stay excluded because they can refresh.
- 0f009a8: Six more environment variables never reach Claude Code from your process's environment, in either preset (`'harness'` and `'inherit'`). Each loads code or configuration, re-routes traffic or weakens a protection in Claude Code 2.1.302:
  
  - `CLAUDE_CODE_REMOTE`
  - `CLAUDE_CODE_ENVIRONMENT_KIND`
  - `CLAUDE_CODE_REMOTE_MCP_CONFIG`
  - `CLAUDE_CODE_DESKTOP_SKILLS_PLUGIN_DIR`
  - `CLAUDE_CODE_SANDBOX_LEAVE_DENIES_TO_SRT_WIN`
  - `CLAUDE_CODE_CCR_WORKER_SOCKET`
  
  When your environment holds one, it is reported in `env.dropped`. To pass one on, set it with `env.add` or an explicit map; the security posture then lists it in `env.credentialAndRoutingVariables`.
- f58ea1e: The `managedPolicy` posture entry no longer has the value `'unknown-raw-settings'`. It could never be produced: `/raw` refuses `--settings` in every spelling and hudhud never passes the flag. Code that matched on the value can drop the case; the remaining values are `'fetched-if-eligible'`, `'not-fetched-custom-base-url'`, `'not-applicable-third-party-provider'`, `'unknown-project-settings-unreadable'` and `'unknown-user-settings-unreadable'`.
- a5696c7: Renamed from `@hudhud/claude-code` to `@hudhudjs/claude-code` (ADR-0004 amendment, 2026-10-16): the npm scope `@hudhud` belongs to another account. Import it as `@hudhudjs/claude-code` and, for the unstable tier, `@hudhudjs/claude-code/raw`; the schemas are `@hudhudjs/claude-code/schemas/*.json`. It depends on `@hudhudjs/core`. Exported names (`connect`, `session`, `hudhud`, ...), error codes and `HUDHUD_*` variables are unchanged.
- dbbdda5: A turn whose user message the harness drops now fails instead of waiting forever (research 10 §3, lead decision after macOS gate run 2). Claude Code 2.1.296 answers a user message whose `uuid` the session transcript already holds with `command_lifecycle` `completed` and never starts a turn for it. The turn machine correlates `command_lifecycle` frames strictly by the turn's `uuid`, before or after `system/init`, and fails a queued turn that reports `completed` without `started` with the new error code `TURN_DROPPED` (class `TurnDroppedError`, retryable: a new send carries a fresh id; `details.turnId`, `details.lifecycle`) and the new diagnostic `turn.dropped` with the observed states. Every other turn is untouched, and a `result` that arrives first still settles the turn once. Both codes are additive in the errors and events schemas.
- 83115cd: Claude Code wire schemas (`@hudhudjs/claude-code/schemas/wire-inbound.schema.json`, `wire-outbound.schema.json`): lenient inbound envelopes and strict outbound frames, so `initialize.workspaceTrust` cannot be sent. Only fields seen in observed frames or the MIT Python SDK are modelled (ADR-0015); system prompts are passed through the documented CLI flags, not `initialize`.
- 57d4fb0: Claude Code option schema (`@hudhudjs/claude-code/schemas/options.schema.json`): strict JSON Schema of the connect and session options, generated from the TypeBox sources with precompiled validators and no run-time schema dependency. The adapter's protocol machines, option resolution, argv and environment builders land internally and are exported with `connect` and `session` in a later wave.
- edc649b: Wave 3 of the Claude Code adapter, internal until `connect` and `session` are exported: the session machine on the neutral contract (handshake first in every mode, user messages held until the `initialize` response, close and abort with K12 and K13, auth fail-fast for `ANTHROPIC_API_KEY`, oversized frames, the idle watchdog), binary discovery (option, native installer launcher, sanitized `PATH`) and the committed provenance table with the pinned Windows publisher, the project credential guard (K5, L1; credential, routing and TLS-trust variables), the posture entries with `managedPolicy` (K23), and the golden conformance fixtures of plan section 4.3 for Windows and Linux, including the K10 `ANTHROPIC_AUTH_TOKEN` fixture.
- 0f4bd1e: Wave 4 of the Claude Code adapter (not yet exported; the connect pipeline wires these modules in Wave 5).
  
  - The capability set, tested window and live session registry (W4-T3). `claudeHarnessCapabilities` builds the Harness capabilities; `parseFeatures` validates the feature strings of `system/init` and the `initialize` response (at most 256 entries of at most 128 characters in a restricted alphabet, unknown names kept, the rest dropped), and the session machine reads feature strings through it; `CLAUDE_CODE_COMPAT` and `compatStatus` give the tested window (a version outside it, or not parseable, is `untested` and only reported; a listed one is `known-broken`, which the Wave 5 connect refuses with `HARNESS_VERSION_KNOWN_BROKEN` unless `claudeCode.dangerouslyAllowKnownBrokenVersion` is set); `SessionRegistry` refuses a second live session id within one Harness with `SESSION_ID_IN_USE`.
  - `encodeClaudeUserInput`: the neutral `UserInput` as Claude Code user-message content (text blocks as is, image blocks as base64 `source` blocks), for the driver's `encodeUserInput` hook.
  - The session machine answers the neutral `cmd.permission-error` fail-closed: the non-interrupting deny of a failed handler (of a refused decision for `invalid-decision`) and `permission.resolved` deny, without a second diagnostic.
- bf49874: The Claude Code adapter assembly (Wave 5), now the public API of the package root and of `/raw`.
  
  - `connect`, `session`, `hudhud` and the `ClaudeCodeHarness` (`sessions.create`, `sessions.resume`): validation, the project credential guard, the cwd, discovery, verification with the pinned publisher, exactly one `--version` probe per connect, the version policy, the security posture and the capabilities; per session the spawn gate (a changed binary is verified and probed again before it runs), the registry claim, the spawn with the job assignment inside it, and the session driver with the Claude session machine, the user-input encoder and the sweep after a graceful close. Every failure maps to its public error class; nothing is left running when a call rejects.
  - Version policy: every known-broken listing carries a committed reason (`details.reason`); a known-broken probed version is refused with `HARNESS_VERSION_KNOWN_BROKEN` unless `claudeCode.dangerouslyAllowKnownBrokenVersion: true` (new option, listed in `securityPosture`); a session whose harness drifted to a known-broken version fails closed, and every drift emits `binary.version-changed`.
  - Under `projectCredentialEnv: 'allow'` the guard's scan still runs (`scanProjectSettings`): its findings feed `managedPolicy` and the diagnostic `settings-guard.allowed`.
  - Public API (W5-Z). The root exports `connect`, `session`, `hudhud`, `CLAUDE_CODE_COMPAT` and the types `ClaudeCodeHarness`, `ConnectOptions`, `ClaudeCodeConnectOptions`, `SessionOptions`, `ClaudeCodeSessionOptions`, `ResumeOptions`, `PermissionMode`, `WorkspaceTrust`, `SettingSource` and `EnvOption`; `/raw` exports `raw`, `createSessionRaw` and the types `RawSession`, `RawSpawnOptions`, `RawFrame`, `RawWireFrame` and `RawGap`, with type-only re-exports of the root types its signatures name. `SessionOptions.onPermission` is typed with the core `PermissionHandler`.
  - The raw tier: `raw(session)` (frames in both directions; raw control requests and frames only with `claudeCode.dangerouslyAllowRawControl`) and `createSessionRaw` (spawn extras without the reserved flags or pinned variables).

### Patch Changes

- 6dc860a: Every option and every public member of the stable entry points now has documentation in the types, so editor hover shows its meaning, default, units and limits (pre-release review R5-8): for example that `SessionOptions.signal` covers only the start of a session, that `closeTimeoutMs` runs from the `close()` call, and the range of every size and duration option. The types themselves are unchanged.
- 0f4eed6: Long-running sessions no longer grow memory with their number of permission requests. A session now remembers the ids of the last 1024 permission requests to arrive or end, each by a key of at most a few hundred characters, instead of every id it ever saw (copied on each request, so the work grew quadratically). A request that reuses one of those ids is still denied without asking (`permission.duplicate-request-id`); an older id is asked as a new request. An id that is forgotten and then reused is asked again, never decided automatically, so forgetting fails safe. Forgetting cannot apply an earlier decision to the new request: by then no answer for the earlier request is left in the session.
- 7e6cd2a: Requests Claude Code sends that hudhud never answers (`remote_*`, `request_user_dialog`) are now remembered at most 64 at a time, the oldest forgotten first, each by a key of at most a few hundred characters; before, a long-running session kept every one Claude Code never cancelled. Nothing is written for them either way; a cancel of a forgotten one is reported as `control.unknown-cancel`.
- ac03c87: The `env.dropped` diagnostic now names exactly the parent variables the child's final environment lacks. A variable that the preset filters out but hudhud pins again (such as `DISABLE_AUTOUPDATER`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, or `TRACEPARENT`/`TRACESTATE` with `trace`) reaches the child with hudhud's value and is no longer listed; a name set again by `env.add` is reported in `env.added` only. The child's environment itself is unchanged.
- c63d27f: The project credential guard resolves the user's config directory from Claude Code's own environment, as the security posture does. Before, with an explicit `env` map that did not pass the parent's `CLAUDE_CONFIG_DIR` on, the guard skipped the parent's directory while Claude Code used `~/.claude`, so the guard's ancestor fallback could read `~/.claude/settings.json` as project settings and refuse a session because of the user's own settings.
- 7d01f08: The `'harness'` env preset now serves every provider switch of Claude Code 2.1.296. With `CLAUDE_CODE_USE_ANTHROPIC_AWS` (Claude Platform on AWS) or `CLAUDE_CODE_USE_MANTLE` (Bedrock Mantle) on, it passes your `AWS_*` variables; with `CLAUDE_CODE_USE_ANTHROPIC_GOOGLE_CLOUD` (Claude Platform on Google Cloud) on, your `GOOGLE_*` and `GCLOUD_*` variables. With either Google switch, the lower-case `gcloud_project` and `google_cloud_project` pass too. Before, these were dropped and had to be added with `env.add`.
- 967da52: On Windows the `'harness'` env preset now passes `PSModulePath` and `PSModuleAnalysisCachePath` on to Claude Code. Before, they were dropped, so PowerShell modules installed outside Windows PowerShell's default directories resolved in your terminal but not in Claude Code's PowerShell tools. Both are paths, not credentials.
- a91a3d0: With `CLAUDE_CODE_USE_VERTEX` on, the `'harness'` env preset now also passes `VERTEX_*` (such as the per-model regions `VERTEX_REGION_CLAUDE_*`) and `GCLOUD_*` (such as `GCLOUD_PROJECT`) from your environment to Claude Code. Before, they were dropped and had to be added with `env.add`.
- 70dbfdd: An interrupt whose answer still lists the turn as queued, arriving after stdin closed, now fails with `SESSION_CLOSED` instead of arming a re-send that could never be written; the application's interrupt no longer waits for the process to exit (found by the turn-machine model check).
- 420e443: Every package now ships the repository's `NOTICE` file next to its `LICENSE` (Apache-2.0 §4(d)). No code changed.
- 6833599: Every published package's `package.json` now names its source: `repository` (this repository and the package's directory), `homepage` and `bugs`. npm trusted publishing requires `repository.url` to match the repository the package is published from. No code changed.
- 66f6b43: Raw tier (`@hudhudjs/claude-code/raw`, unstable): `controlRequest` now lets at most 64 requests (`RAW_CONTROL_MAX_IN_FLIGHT`, new export) wait for an answer at once per session. One more is refused at once with `ControlRequestError` (`CONTROL_REQUEST_FAILED`, `details.cause: 'in-flight-limit'`, `details.limit`) and nothing is written. Before, requests Claude Code never answered stayed until the session ended, since a raw request has no default timeout; pass `timeoutMs` or a `signal` for requests that may go unanswered.
- 966c2dd: Disposing a Harness now waits for every session start in flight (pre-release review, R4-2). A start whose Claude Code process was being spawned when dispose began ends that process itself and rejects with `HARNESS_DISPOSED`; before, dispose resolved at once and the new process ran on until its handshake or the first-frame watchdog (up to 60 s). A start that has not spawned yet stops at its next step with `HARNESS_DISPOSED`, and every call of `[Symbol.asyncDispose]()` returns the same complete promise.
- bafa718: An abort stops a running version probe at once (pre-release review, R5-U1). `connect({ signal })`, and the `signal` of a session start that probes a changed binary again, used to act only after the `--version` probe ended (up to its 15 s bound); now the probe's child is killed through its handle and the call rejects with `ABORTED` right away, with nothing left running. Hashing the binary and the OS signature check still complete before the abort is seen (both are bounded).
  
  Process API: `BoundedCommand.signal` (aborting it kills the child; already aborted, nothing is spawned), the new `CommandOutcome` kind `'aborted'`, `VersionProbeOptions.signal` and the `VersionProbeFailure` reason `'aborted'`.
- 011f035: Process layer fixes from the pre-release review (ADR-0009, ADR-0010).
  
  - A tool's daemon no longer outlives `dispose()`, an aborted `close()` or a close deadline on Linux and macOS. Whenever a snapshot of the tree exists, it is swept after Claude Code exits, whichever step ended it: the POSIX ladder sweeps S1 (and S2) as soon as it sees the exit, and the binding snapshots the tree before every end of input once a ladder runs. The `termination.sweep-after-exit` diagnostic now also follows a ladder.
  - Windows: the sweep after the exit never adopts a process whose parent pid only names a dead tree member. It follows the dead root only for children started before the host saw its exit, and other parents only while they are alive with their verified identity. With a job there is no snapshot and no sweep: closing the job ends the tree. `AfterExitSkipReason` gains `'job-closed'` and `'job-close-failed'`, and `AfterExitDeps` gains `rootExitObservedAt`.
  - Windows best effort: the ladder no longer skips `taskkill /T` when a process with a stale parent pid names a tree member (step detail `identity-foreign-child`). Measured: `/T` leaves such a process alone.
  - Linux: with `/proc` mounted `hidepid=1`, unreadable entries are skipped and counted instead of failing the snapshot. The count shows as `rejected-<n>` on the ladder's snapshot steps and as `rejected` in the after-exit report. A `/proc` that belongs to another pid namespace is refused, so the session uses the degraded path instead of reading other processes.
  - macOS: `ps` runs with `-ww`.
- 88ef13b: Raw tier `frames()` (pre-release review, ADR-0007):
  
  - A full `overflow: 'block'` raw subscriber now stalls the session instead of breaking it. The inbound tap and every outbound write publish through one serialized chain; before, a write during a stall made a second publish throw, so the session took it for a broken input pipe and refused every later call with `SESSION_CLOSED` (or stopped reading Claude Code's output on the read path).
  - The session option `events.signal` ends `frames()` subscriptions with `ABORTED`, as it does for `events()`, and a subscription lets go of its signals once it stops accepting frames.
- 645d5ec: Raw control checks what it writes (pre-release review, R4-8). `RawSession.writeFrame` and `controlRequest` checked the caller's object and then serialized it again, so a getter or a proxy could pass the checks with one value and write another (for example a permission update to `userSettings` without `dangerouslyAllowConfigWrites`). The encoded line is now parsed back and checked once more under the same rules, and exactly that line is written. A getter or proxy trap that throws is refused with `INVALID_OPTIONS` instead of escaping as a plain `Error`: `isJsonValue` returns `false` for such a value and `encodeJsonLine` returns `PROTOCOL_ERROR` (`not-serializable`), as both functions document that they never throw.
- be3d47f: `usage.update.estimatedDelta` now carries figures (pre-release review, R4-7; ADR-0016). It was always `{ estimate: true }` with nothing else. Claude Code reports each turn's own main-loop tokens and a running cost total in its `result` frame; the estimate is the turn's tokens as reported and the change of the running cost since the session's previous report (a smaller total counts as a reset). The first report of a resumed or forked session has no cost delta, since its baseline is unknown. `usage.update.reported` and `TurnResult.usage` are unchanged; the guide now states what they hold (the tokens are the turn's own, not cumulative as it said).
- 2aba9a4: The schemas now import by their file names, as documented (pre-release review R5-6): `@hudhudjs/core/schemas/events.schema.json` and `@hudhudjs/claude-code/schemas/options.schema.json` resolve to those files. Before, the `exports` map added `.json` to every specifier, so the `.json` form looked for `events.schema.json.json` and failed with `ERR_MODULE_NOT_FOUND`. The form without `.json` still works. Import a schema with the attribute `{ type: 'json' }`.
- 1c8fcf7: `NOTICE` now says that a package lists its third-party code after the repository's notice. `@hudhudjs/claude-code` lists the MIT-licensed code its generated validators include (Ajv's runtime helpers and fast-deep-equal), with their license texts. No code changed.
- 8cdccc4: A `system/init` that Claude Code repeats while a turn it started itself is still open (no `result` or `idle` in between) no longer opens another harness turn: it belongs to the open turn, and the new diagnostic `turn.repeated-init` (added to `DiagnosticCode` and the events schema) reports the protocol drift once per such turn. Before, each repeat opened a new `bg-<n>` turn that stayed until an `idle`, so a harness repeating it could grow the turn table without bound. Claude Code itself is not known to do this.
