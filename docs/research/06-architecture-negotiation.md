## A. Settled (all Fable replies converged on these)

A1 Foundation: hudhud's own implementation of the stream-json + control protocol against the user's installed, unmodified CLI. Wire types derived from observed frames + MIT Python SDK (NOTICE). Nothing from proprietary sdk.d.ts. Legal review before open-sourcing.
A2 Claude Code adapter backends: `native` (any duplex stream: local spawn, custom spawner) and `agent-sdk` (optional peer dep, never redistributed, wired via spawnClaudeCodeProcess over hudhud's process layer; also a CI differential oracle). No SDK-identity/entrypoint spoofing.
A3 Public API: connect() -> Harness (capabilities, binary info, sessions.create/resume) -> Session (ask(), send() -> Turn {id, done, interrupt(), filtered iteration}, events() session-wide). hudhud.session() sugar. Open event union (`type: string & {}` arm + raw). Three tiers: stable / harness-namespaced options / unstable `/raw` subpath. Symbol.asyncDispose + AbortSignal everywhere. Session<->process binding is adapter-internal and may be one-to-many.
A4 Packages: pnpm monorepo, ESM-only, Node >= 22. Published @hudhud/core (subpaths /protocol, /process; schemas/), @hudhud/claude-code (+ /raw), `hudhud` umbrella, @hudhud/win32-job-{x64,arm64} optional platform packages. Integer adapterApiVersion negotiated at registration. Changesets, API Extractor.
A5 Schema: committed JSON Schema 2020-12 = the contract. TypeBox authoring, build-time only, major pinned, documented fallback (json-schema-to-typescript). Validators precompiled from the committed schema with Ajv standalone; no runtime eval; zero runtime schema dependency. Additive-only diff linter. Open enums, `x-` experimental namespace, mandatory raw. Validation: strict public inputs, strict outbound frames, lenient envelope-only inbound.
A6 Sans-IO core: pure state machines (state, input) -> (state, effects[]); injected clock/ids; no IO imports in core (lint + dependency-cruiser); callbacks are id-correlated request/response messages with optional deadline + cancel; TS closures are a binding layer. JSON-only boundary (ISO timestamps + seq, string ids, no bigint/Date/class instances, base64 binary, absent-only optionality, errors as data). Loopback binding in v1 proves the boundary. Golden fixtures as language-neutral JSONL conformance suites.
A7 Multi-language: a later daemon (JSON-RPC 2.0 over NDJSON, local authenticated channel only, never TCP by default) with thin generated clients; not native ports.
A8 Defaults: user's real config dir, never-write posture; isolated CLAUDE_CONFIG_DIR and --bare are opt-in only. Explicit --permission-mode always. stdio permission prompting only when a handler is supplied. Non-session permission destinations stripped and update_settings never sent unless explicit opt-in. permission_suggestions never auto-applied. env preset 'harness' (default) | 'inherit' | explicit, with dropped-name diagnostics. DISABLE_AUTOUPDATER=1. Every depended-on behaviour pinned by explicit flag. Hudhud always generates and passes --session-id.
A9 workspaceTrust ordered enum 'none' | 'context' | 'full', default 'none' (settingSources ['user']); 'context' capability-gated. Owner must confirm defaults.
A10 Event delivery: stdout always drained; control frames dispatched independently of consumers; firehose = opt-in per-subscriber bounded queues (count+bytes); default overflow 'error' scoped to that subscriber; 'drop-oldest-with-gap-marker' opt-in; ask()/turn.done never depend on subscribers. A11 Turn semantics: queue interrupt until the turn's system/init; synthesize turn-end from session_state_changed idle or process exit when result is absent; stdin-close policy modelled on SDK's bidirectional-needs rule with a ceiling. A13 Windows ladder: interrupt -> EOF -> TerminateJobObject; best-effort fallback EOF -> taskkill /T /F (absolute System32 path, shell:false) -> TerminateProcess. Capability processContainment 'job' | 'best-effort' from v1; addon is a 1.0 criterion (in v1 if spike green).

## D. Spike results (research/05-empirical-cli.md, CLI 2.1.296, Windows + Linux; lead reviewed)
D1 Hashes: win32-x64 and linux-x64 binaries match npm integrity AND manifest.json SHA-256; SDK's win32 binary byte-identical to claude-code's.
D2 No -p needed; --verbose mandatory. initialize optional; system/init once per turn after the user message; with nothing on stdin the CLI waits forever.
D3 can_use_tool only with --permission-prompt-tool=stdio. Unanswered request waits forever (no CLI timeout, CLI never sends keep_alive). Interrupt -> CLI sends control_cancel_request for pending permission. Without the flag in --permission-mode=default, mutating commands auto-denied.
D4 WITHOUT --permission-mode the session starts in `auto`: mutating Bash ran with no can_use_tool even with stdio prompting. Explicit --permission-mode is mandatory.
D5 GH#98713 reproduces: interrupt in the same write as a turn-2 user message is ignored; a gap after system/init fixes it (confirms A11).
D6 stdin EOF: CLI finishes the running turn + queued work, exits 0 ~30-60 ms later. Exit code: 1 iff last result is_error; 1 for invalid flag / garbage stdin. Windows job close -> exit code 0; Linux SIGTERM 143, SIGHUP 129, SIGINT 0 with NO result frame. "Exit 0" can mean killed.
D7 Windows tree: TerminateProcess(claude.exe) orphans git-bash tree 4/4. EOF leaves no orphans. Spawned normally (NOT detached, i.e. already inside libuv's job) and then assigned to a second KILL_ON_JOB_CLOSE job: nesting works, CLI behaves normally, grandchildren inherit the job (no breakaway), job close kills everything. Assignment race window exists between spawn and assign (assign before first stdin write). => C1 resolved: no `detached` needed.
D8 Linux tree: CLI puts EACH Bash tool in its OWN process group. SIGTERM/SIGINT -> CLI cleans tool groups (no survivors). SIGKILL to CLI or kill(-pgid of CLI) -> bash/sleep SURVIVE. => A12 is WRONG: POSIX process-group kill is insufficient. Options: cgroup v2 (systemd scope / delegation, not universal), PR_SET_CHILD_SUBREAPER (native; host becomes reaper of all orphaned descendants -> zombie accumulation since libuv only reaps its own children), /proc descendant walk (racy, Linux-only; macOS needs libproc/sysctl), or rely on SIGTERM + documented residual. macOS untested.
D9 Line sizes: bounded by model output; 5 MB model text -> three ~5 MB lines (stream_event, assistant, result each carry full text). 1 MiB cap too small; default cap 32-64 MiB configurable.
D10 UTF-8 clean both ways incl. Arabic through Bash and PowerShell tools; CRLF, BOM, split multibyte writes tolerated.

## E. Lead's independent positions for the final round (to be argued, not assumed)
E1 POSIX containment (new, from D8): reject PR_SET_CHILD_SUBREAPER (global side effect on the consumer's process + zombies). Proposal: ladder EOF -> interrupt -> SIGTERM to CLI (proven to clean tool groups) -> SIGKILL CLI + descendant sweep. Sweep on Linux via /proc (collect descendant pgids BEFORE killing the CLI, while the tree is intact; kill each pgid), macOS via `ps -A -o pid,ppid,pgid` parsed by absolute path /bin/ps (no native code) or libproc in a future darwin addon. cgroup v2 as an optional "strong" containment when delegation exists (capability processContainment: 'cgroup'). Crash-of-host residual documented. Fable to attack.
E2 Ajv standalone output can `require("ajv/dist/runtime/...")` helpers (ucs2length, equal, uri, validation error) for some keywords; "zero runtime schema dependency" only holds if we bundle those helpers into the generated module at build time (esbuild) or avoid those keywords. Proposal: bundle + a CI check that the published dist has no `ajv` import.
E3 pnpm over npm on merit: strict non-flat node_modules (no phantom deps), install scripts blocked by default with an explicit onlyBuiltDependencies allowlist, minimumReleaseAge to delay freshly published (possibly hijacked) versions, catalogs for single-version deps across the monorepo, deterministic lockfile. Consumers are unaffected (they install published packages with any manager).
E4 Umbrella `hudhud` package: keep, but only as a zero-code re-export with exact-version deps, so `npm i hudhud` is the simple path; it must never contain logic.
E5 Sans-IO cost control: apply sans-IO strictly to the protocol/turn/permission state machines (where it pays off in determinism and daemon-readiness); the process layer and the binding layer are ordinary async code. Do not force sans-IO onto everything.
E6 Node support: engines >=22 (Node 22 maintenance until 2027-04), CI matrix 22/24/26; drop 22 in a major after its EOL. Decision driver: consumers (Electron 33+ ships Node 22).
E7 NONESSENTIAL traffic default (D14): do NOT set it by default for real users (it changes the user's harness behaviour; R6 spirit), expose it as an option; tests always set it plus the egress trap.
E8 Exit-code semantics: hudhud never infers "success" from exit code; turn/session outcome is derived from frames + hudhud-observed kill reasons (D6).
E9 Hooks timeout default must match the timeout hudhud declares in initialize.hooks[].timeout (single source).
E10 Framer default cap 64 MiB, configurable; enforce per-line, and on overflow fail the session with a protocol error (never truncate silently).

'full' documentation states plainly: project hooks, MCP servers and env run without any trust dialog, and without the guard the repository could redirect API traffic and credentials.
J3 B4 resolved (07 §10): `initialize.workspaceTrust` is a persisted trust grant (writes `hasTrustDialogAccepted` to the user's `.claude.json`, widens project permission rules for future sessions), not a loading filter. hudhud never sends it by default (R6). `workspaceTrust 'context'` stays unsupported in v1 (native path ruled out; only the emulated audit remains possible later). Exposing the grant is deferred to v1.x as a separate `dangerously*` boolean, never part of 'full'. Untrusted project `permissions.allow` entries are ignored by the CLI with a stderr notice; hudhud surfaces it as a diagnostic.
J4 E9 resolved (07 §8): the hook timeout unit is seconds for hook callbacks and settings hooks; CLI callback default 600 s; a callback timeout blocks the tool (fail-closed) and the CLI sends `control_cancel_request`; a settings command-hook timeout is fail-open. hudhud keeps its 60 s default with the handler timer 2 s shorter and passes the timeout in seconds.
J5 Stdin-close ceiling resolved (07 §7): `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS` default 600000, 0 = unlimited; on expiry it stops background subagents but NOT background Bash shells (one held the CLI 697 s). Drain on `close()` therefore needs hudhud's own deadline (`closeTimeout`, illustrative; default 30 s) after which the abort ladder runs; hudhud does not change the ceiling by default (an option to set it exists).
J6 Resume/fork resolved (07 §1): no CLI-side session lock; two processes resuming one session diverge (last-written branch wins). hudhud refuses a second live resume/create of the same session id within one Harness (typed error) and documents the cross-process hazard. `--continue` with no history silently starts a new session, so hudhud's `continue` reports `resumed: false` by comparing ids. A nonexistent id yields a `result/error_during_execution` before the initialize response and exit 1, mapped to a typed `SessionNotFound` error. Fork gives a new id (or the passed `--session-id`). The G4 resume gate is removed.
J7 Protocol (07 §11.4): the protocol layer must accept a `result` frame before the initialize response (failure path).
J8 Host crash resolved (07 §2): under a Node host on Windows, libuv's job kills the CLI about 33 ms after host death without graceful shutdown, and Git-Bash tool trees are orphaned; the job addon (KILL_ON_JOB_CLOSE on hudhud's own nested job) is therefore required for crash cleanup too, reinforcing it as the 1.0 criterion. Linux and Windows detached: the CLI sees EOF and drains gracefully, no orphans.
J9 pid resolved (07 §4): `initialize.pid` equals the spawned pid only for the directly spawned native binary; behind a launcher it differs. Process identity always uses the pid hudhud spawned (plus start time); `initialize.pid` is informational and a mismatch is reported as a diagnostic (launcher detected).
J10 Long paths resolved (07 §6): a Windows cwd of 259 characters or more fails with a misleading ENOENT; a `\?\` prefix makes the CLI use the 8.3 short name (splits transcripts, Bash refuses writes). hudhud validates cwd length on Windows before spawn and throws a named error (`CwdTooLong`, illustrative); it never auto-prefixes.
J11 Concurrency resolved (07 §5): concurrent sessions sharing one config dir are safe in steady state; a first-write race exists only on a fresh config dir. Test fixtures pre-initialize config dirs; production is unaffected (the real config dir exists).
J12 Test mock (07 §0.2, §11.5): hudhud's own test mock must survive reset CONNECT sockets (a bug found in the spike mock); a test for it is required.
