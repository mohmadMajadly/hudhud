The project credential guard (`projectCredentialEnv: 'refuse'`, the default whenever project or local settings load) now refuses the third-party provider routing and credential variables too, by family rather than by an exact list: every `ANTHROPIC_*`, `AWS_*`, `GOOGLE_*`, `GCLOUD_*`, `CLOUDSDK_*`, `CLOUD_ML_*`, `VERTEX_*`, `AZURE_*`, `CCR_*` and `CLAUDE_CODE_USE_*` variable except model selection (`ANTHROPIC_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL`, `ANTHROPIC_DEFAULT_*_MODEL` and their display companions); `CLAUDE_*` variables with a credential, routing or configuration segment (`CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CODE_API_BASE_URL`, `CLAUDE_CONFIG_DIR`, ...); every proxy variable except the `NO_PROXY` forms; and every TLS-trust variable. Before, a repository could set `CLOUD_ML_REGION`, `AWS_REGION` or `ANTHROPIC_FOUNDRY_RESOURCE`, from which Claude Code builds the provider host, and receive the provider credential. A repository that sets such a variable is now refused with `PROJECT_CREDENTIAL_ENV`; set the variable from the application with `env.add`, or opt in with `projectCredentialEnv: 'allow'`. The names are also listed in `securityPosture` (`env.credentialAndRoutingVariables`) when the application sets them.
